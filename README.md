# DailyScreen Lite

个人本机的候选导入与候选归类工作台。首版聚焦：**导入候选 → 解析校验 → 落库 → 当天可归类的股票卡**。

顶部导航为 **导入 / 候选归类 / 观察组** 三个同级业务模块，右侧提供全局搜索、数据中心与设置；
每个模块各占完整工作区并独立保留自己的位置与筛选，"研究"一词留给未来的深度研究模块。
每次新打开应用先看到**沉浸式启动页**（导入候选、开始归类、观察组、更新数据四个入口），
模块切换和网页刷新不重入启动页；刷新保留当前模块，点击左上角标识才返回。

技术栈：Python 3.14 + FastAPI + SQLite（后端），React 19 + TypeScript + Vite + Tailwind（前端）。
本机运行，独立存储，不依赖完整版 DailyScreen。

### 环境前置

- **Python 3.14**（后端与测试）。
- **Node 24**（`package.json` 的 `engines` 为 `>=24 <25`）：构建前端与运行问财令牌生成器。
- **pnpm 12.3.4**（`package.json` 的 `packageManager` 锁定此版本）：安装前端依赖；用其他包管理器会绕过锁文件。

版本不符时先切换 Node／pnpm 再继续，前端构建与端到端都会按这里的版本假定运行。

## 快速开始

### 1. 准备后端

```powershell
python -m venv backend\.venv
backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
backend\.venv\Scripts\python.exe -m pip install -e backend
```

运行测试或重建证券库快照需要开发依赖（含 pytest、httpx、duckdb）：

```powershell
backend\.venv\Scripts\python.exe -m pip install -r backend\requirements-dev.txt
```

> 若本机 pip 指向的镜像缺少依赖版本，追加 `-i https://pypi.org/simple` 或 `-i https://mirrors.aliyun.com/pypi/simple/`。
> 国内镜像可能未收录 `akshare`；缺失时用 `-i https://pypi.org/simple` 安装。

### 2. 构建前端

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm run build
```

### 3. 启动

双击 `start.bat`，或手动运行：

```powershell
backend\.venv\Scripts\python.exe -m dailyscreen_lite --host 127.0.0.1 --port 8765
```

浏览器打开 <http://127.0.0.1:8765>。

开发模式（后端 + 前端热更新，一条命令）：

```powershell
python dev.py            # 等价于 python dev.py start
python dev.py status     # 查看两个进程与访问地址
python dev.py stop       # 停止
python dev.py restart
python dev.py build      # 构建前端产物（生产模式用）
python dev.py test       # 运行后端测试，其余参数透传 pytest
```

`dev.py` 同时启动后端（uvicorn :8765）与 Vite 开发服务器（:5173，热更新，`/api` 代理到 8765），
开发入口为 <http://127.0.0.1:5173>。两个进程在后台运行，日志写入 `data/runtime/dev/`，
启动后即可拿回终端。它与 `start.bat` 共用 `data/runtime/` 的同一份数据，并同样启用每日
16:30 至 22:30 每小时有限补取与白天启动补更，因此开发时看到的是真实数据、也会触发正常的数据更新。

若只想单独跑前端开发服务器（后端需另开）：

```powershell
cd frontend
pnpm run dev
```

## 使用

在导入模块的同一个输入框完成混合提交（每个文件、文本块或链接各自成批次，互不影响）：

1. **文件**：点击「添加文件」或拖入 CSV / TSV / TXT / XLSX（需含股票代码列）。选中后进入待提交列表，点「提交」才真正处理，提交前可逐个移除。
2. **文本**：键入或粘贴每行一个代码，或粘贴含代码列的表格（逗号/分号/制表符/竖线/空白分隔）。
3. **问财链接**：单行粘贴问财结果链接，按链接获取完整结果。首次或条件口径变化时展示原句与解析条件，确认后发布；同查询同口径后续自动发布。
4. **歧义选择**：出现多个候选代码列或多个工作表时，卡片展示最小预览并要求选择；列名指示非代码语义（如成交额、序号、价格）的列不会被自动采用。
5. **本次导入结果**：汇总"新增 / 合并 / 重新归类 / 跳过"，并逐行给出股票名称（来自权威证券库）、代码、导入结果与备注；未识别股票在折叠明细中列出原始代码与位置。导入成功停留在结果页，由用户点击「开始归类」进入候选归类（队列已在后台更新，不强制跳转）。
6. **最近导入记录**：列出导入时间、来源与识别结果，点击任一条即可查看它的完整结果；超过五条时可「查看更多」。失败批次保留原因，可「重试该批次」；跳过的股票可「重新识别跳过项」按原导入日期补入，仍未知的明细直接清除。
7. **候选归类**：左栏是候选队列（待归类／已处理两个页签、全部日期筛选、列表／卡片切换，并显示最新收盘价与当日涨跌幅），右栏是当前股票卡。打开工作区或改筛选读一次统一浏览结果（当前卡、完整轻量列表与数量来自同一读取视图）；普通切卡只更新卡片与列表变化，不重传整份列表。列表只渲染可见行，长队列滚动时不同时渲染全部行。归类动作保存成功后自动打开下一只；底部紧凑的「上一个／下一个」可沿本轮访问历史回看和继续，回看不撤销归类。手动点选或从全局搜索打开候选会成为历史中的新一步，中途跳转替换原来的前进分支，且不改变队列顺序与当前筛选。当前筛选范围看完后显示可跨重启恢复的结束卡（结束卡本身也是可回看的一步），仍如实显示剩余待归类数量；点「返回队列」重置本轮。
8. **一只股票最多一个候选项**：未处理期间跨日再次入选合并到同一对象（保留原队列位置与各次入选日期），同日其他来源只追加追溯、不再次触发归类；处理完成后另一个导入日期的首次有效入选会让同一对象重新进入待归类，并保留历次处理记录。
9. **处理动作与回看**：**稍后处理**把股票移到队尾（仍在待归类池），**暂不关注**结束本次归类（导入事实保留），成功后均自动前进；已处理项可在「已处理」页签按结果筛选，并**重新归类**（复用同一对象、保留历史并调到队首）。回看已处理股票时可见其最新状态。
10. **观察关系单向联动**：**加入 / 保留观察**只增加所选关系（原有组保留）并完成本次归类（可在浮层里直接新建组）；已观察股票的卡片另有**移出观察组**，弹框支持单选、多选、全选，确认移除所选关系的同时记为暂不关注，取消不改变任何状态。观察关系的变化不会反向改变候选处理状态。
11. **观察组模块**：左栏是组列表（汇总视图 + 单组，支持新建、重命名与删除），中间是按证券去重的观察股票表，右侧是同页个股详情。组只有删除、没有归档：删除只移除该组关系，股票在其他组的归属、笔记、来源与处理历史都保留；默认组也可以删除，删至无组时显示空状态，重启不会重建已删除的默认组。
12. **观察列表**：显示名称/代码、最新收盘价、对应行情日涨跌幅、实际行情日期与所属全部现存组；默认按加入时间倒序，可按名称或涨跌幅排序。行情缺失时留空占位，不影响浏览。可用「调整观察关系」转组、多组归属或退出全部组，这些操作不改变候选处理状态。
13. **共用个股详情**：归类卡片与观察组详情复用同一份内容（股票信息、观察关系、行情、笔记、来源与处理记录），以股票而非某次候选项为身份，跨导入日期与入口共享；来源与处理记录默认收起。详情可展开为完整页面，返回后组、排序与列表位置不变；观察页不要求先完成归类动作。
14. **来源与处理记录**默认收起，点卡片上的小触发入口可展开查看各次入选日期、全部来源与历次处理记录。
15. 「清理待归类池」把当前待归类项移出工作池（不改导入事实），可按入选日期限定。
16. **全局搜索**（右上角）：只覆盖已成功导入并识别的股票，不引入全市场名单。打开结果即把该候选作为访问历史的新一步（不改变当前筛选、不重排队列，目标不在左侧当前结果里时卡片明确提示）；已观察且没有待归类对象时打开个股详情，不自动创建待归类对象；仅有暂不关注或清理记录时可以「查看卡片」按原处理状态打开卡片，只有主动点「重新归类」才恢复待处理。
17. **个股笔记**：股票卡与观察详情上可直接新增笔记（Enter 换行，Ctrl/Cmd+Enter 保存），保存不完成归类、不切换卡片、不切换股票；「查看全部笔记」汇集该股票**跨导入日期共用**的同一笔记流，可就地编辑或删除。笔记只保留正文与最近保存时间，没有标签、附件或修订历史。
18. **日线行情**：导入后立即后台补取，卡片与详情展示前复权 K 线与成交量、最新行情日期、来源；日线、周线、月线默认显示当前周期允许的最多根数（上限 500 根，不足时全部显示），可缩放或点「看更早」加载历史。新股票默认获取近三年（晚上市按上市日起），已有股票从最近五根日线的最早日期补取；已达目标交易日的股票在整体更新中跳过，单股刷新仍可复查。行情缺失时明确提示「行情暂未取得」，不画空图、不用零值伪造。
19. **数据中心**（右上角）：分项展示**证券库 / 交易日历 / 股票状态 / 日线**的结论，证券库另列沪深北各市场结果与最近成功时间；更新范围为待归类股票与观察组股票的并集，
    并按股票列出**行情日期、状态与失败原因**（已更新 / 全天停牌 / 待补齐 / 状态待确认），可**重试未完成部分**。
    目标是最新已收盘交易日的完整日线：抓取截止取目标交易日（不写盘中未收盘的日线），请求成功但日期落后仍算未补齐；
    确认全天停牌可豁免当日日线；状态无法确认时显示「未补齐，状态待确认」。
    一次更新的终态按实际完整性给出——仍有股票未补齐就只记「部分完成」（更新记录里注明只数），不把请求结束当全部完成。
    沪深未补齐时业务页面顶部红色提示实际目标交易日，补齐后按实际完整性解除；北交所尽力获取，缺失不触发全局红色提醒，但逐股结果、实际日期与手动重试仍保留。
    证券库提示取自最近一次真正动过证券库的更新，单股与定向任务不会把它抹掉；
    证券库失败单独提示「证券库更新失败，当前使用上次数据」，不把完整行情判为未更新。
    历史股票在详情里可**单股更新**（`kind=single`），只取这一只、不加入持续更新范围。
20. **沉浸式启动页**：首次打开应用先看到它，提供导入候选、开始归类、观察组、更新数据四个入口，
    不展示统计、日期、导航、搜索或数据提醒；背景采用蓝白水彩山水扩图与缓慢流动的轻雾，标题为「看见起伏，守住判断」（系统开启「减少动态效果」时云雾静止）。
    主动更新留在启动页，仅在该入口附近显示进展与结果，失败可「查看详情」；更新期间仍可进入导入、归类或观察组，更新在后台继续。
    网页刷新保留当前模块与服务端保存的工作位置，点击左上角标识才返回启动页；返回后刷新仍停在启动页。
21. 刷新或重启后，批次统计与跳过明细、待处理请求、候选队列与当前股票、筛选与视图、观察组的组/排序/当前股票与成员关系、个股笔记、行情与更新记录、每日状态快照与逐股更新结果都会从数据库读回并展示；各模块独立保留自己的工作位置，模块间不自动同步当前股票。

问财 Cookie 在右上角「设置」中粘贴保存（只写入本机数据目录，不出现在日志或导入结果中）。

## 契约类型生成（后端 DTO → 前端类型）

后端请求／响应模型是传输契约的唯一来源，前端类型由它生成（见 `frontend/src/api/generated/README.md`）。
已接线的功能按模块引用生成类型：笔记（`src/api/notes.ts`）、候选归类与观察联动
（`src/api/classification.ts`）、观察工作表（`src/api/observations.ts`）、证券身份
（`src/api/securities.ts`）；其余端点仍是原有宽泛结构。
两条命令分别在仓库根目录与 `frontend/` 下执行：

```powershell
# 仓库根目录：后端 DTO → frontend/src/api/generated/openapi.json（隔离临时目录）
backend\.venv\Scripts\python.exe -X utf8 backend\tools\export_openapi.py

# frontend 目录：openapi.json → schema.d.ts
cd frontend
pnpm run gen:api
```

检查生成物是否与当前模型一致（重新生成无差异）：

```powershell
# 仓库根目录
backend\.venv\Scripts\python.exe -X utf8 backend\tools\export_openapi.py --check

# frontend 目录
cd frontend
pnpm run check:api
```

`generated/` 下的 `openapi.json` 与 `schema.d.ts` 是生成物、不可手改（同目录的 `README.md` 是手工维护的说明）；普通构建只消费已生成的类型，不会隐式启动后端、联网取 schema 或要求行情供应商可用。

## 数据与配置

- 初始证券库快照：`data/securities/initial_snapshot.json`（随代码交付，5551 只 A 股）。由 `backend/tools/build_securities_snapshot.py` 从授权历史库只读抽取；来源、生效日期与身份指纹记录在快照内。
- 问财令牌生成器：`data/wencai/hexin-v.bundle.js`（随代码交付；上游 MIT，附 `LICENSE`）。问财接口要求随请求变化的 `hexin-v` 头，其算法以 JS 下发，故通过 Node 运行该生成器获取令牌；可用 `DSLITE_WENCAI_BUNDLE` 指向其他生成器。
- 运行数据：`data/runtime/`（SQLite 数据库、导入原件存档与 `secrets.json` Cookie），已在 `.gitignore` 中排除。
- 环境变量 `DSLITE_DATA_DIR` 可覆盖数据目录（端到端测试用它隔离数据）。
- 环境变量 `DSLITE_NOW` 可固定北京时间（ISO 8601，如 `2026-09-12T10:00:00+08:00`）：
  仅用于开发与端到端测试固定"今天"（跨日入选、跨日合并等场景），正式使用不要设置。
- 环境变量 `DSLITE_WENCAI_BASE` 可覆盖问财接口基址（默认 `https://www.iwencai.com`）。端到端测试用它指向本地协议桩，让真实适配器在不访问外网时走完整链路；正式使用不要设置。
- 行情来源：沪深日线优先腾讯 HTTP 直连前复权，失败或日期落后时逐股尝试 AKShare/新浪前复权；北交所优先新浪、再试 AKShare/东方财富尽力获取路径，权威名单和停复牌保持 AKShare。腾讯原始成交量按代码前缀换算为手，新浪成交量由股换算为手；BaoStock 适配器保留但当前不在生产日线链中。测试/回放可注入：
  `DSLITE_QUOTES_FIXTURE` 指向行情夹具 JSON（该文件可选 `adjust`/`source` 声明自身口径），
  `DSLITE_QUOTES_HISTORY_DB` 指向授权历史 DuckDB 只读回放。`DSLITE_UPDATE_SCHEDULE=off` 关闭定时与启动补更。
- 名单按市场独立提交，空、重复、身份异常或无法解释的缺项保留该市场旧名单。沪深名单缩减时通过交易所终止上市资料核对，确认后才移除；无法核对则保旧，北交所尚无准入的退市核对路径。旧库可识别证券仍正常导入，未知代码显式跳过。
- 交易日历直连深交所完整自然月（本月与上月分别校验、保存），请求失败保留可信旧月份；跨月缺覆盖时按工作日给出暂定目标并标明不确定，不把缺日当休市。BaoStock 日历只作实源核对，尚未接入生产备用链。
- 每日状态来源：默认 AKShare/东方财富停复牌区间，与日历独立更新。测试可注入：
  `DSLITE_MARKET_STATUS_FIXTURE` 指向状态夹具 JSON（可给 `calendar_months` 回放深交所原始完整月响应，旧夹具保留 `trade_dates`；以及 `suspensions`、`covered_markets`、`uncovered_markets` 或 `error`），
  `DSLITE_MARKET_STATUS=off` 关闭该来源（状态一律记未知，缺失行情显示「未补齐，状态待确认」）。


它只清空运行库中的业务表与 `runtime/archives/` 下的来源存档，保留 `secrets.json`（Cookie 与连接配置）
与交付资源（`data/securities`、`data/wencai`）；证券库清空后由应用启动时按交付快照重新加载。
工具会先校验清理目标边界（拒绝仓库根、数据目录本身、盘符根与家目录），并把数据库与存档整体备份；
数据库备份走 SQLite 备份接口（`repository/maintenance.py`），已提交但仍在 WAL 中的行不会漏掉。
